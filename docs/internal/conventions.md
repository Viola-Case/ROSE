# Code conventions — ROSE

House style, so new code reads like the code already there. Written against
`master` @ `6870ee3` (**2026-07-24**) from the config files plus what the tree
actually does.

**Order of authority.** Where these disagree, the earlier one wins:

1. `.clang-format` — all whitespace, wrapping, and brace placement. Do not argue with it, run it.
2. `.clang-tidy` — naming (`readability-identifier-naming`) and the enabled bug/modernize checks.
3. This file — everything the tools can't express: comments, headers, layering, idiom.

---

## 1. Comments

### Multi-line comments use `/* */`

**Never stack `//` lines.** A comment that spans more than one line is a block
comment, always:

```cpp
/* Semi-implicit Euler: the rates advance first so the integration below runs against end-of-frame velocities. Costs
 * nothing over the explicit form and does not pump energy into the system when acceleration is nonzero. */
m_drdt += (m_d2rdt2 * dt);
```

not:

```cpp
// Semi-implicit Euler: the rates advance first so the integration below runs
// against end-of-frame velocities. Costs nothing over the explicit form and
// does not pump energy into the system when acceleration is nonzero.
m_drdt += (m_d2rdt2 * dt);
```

`//` is for one-liners only — a trailing note or a single line above a statement.
The moment it needs a second line, convert the whole thing to `/* */`.

Continuation lines carry a leading ` * `, aligned under the opening `/*`. Closing
`*/` may share the last line of text (as above) or sit on its own; both appear in
the tree.

### Doxygen

The public API is documented with Doxygen (`api.Doxyfile`, generated by
`gendocs.ps1`). Three forms are in use:

| Form | For |
|---|---|
| `/** … **/` | The file header block at the top of every file |
| `/*! … */` | Documentation attached to the declaration below it |
| `//!< …` | Trailing documentation for a single member |

```cpp
/*!
 * Canonical FactoryFn for a behavior type; register as `MakeBehavior<MyBehavior>`.
 * The factory builds a blank object, then Deserialize() fills it.
 */
template <RegistrableBehavior T>
UniquePtr<Behavior> MakeBehavior() { return MakeUnique<T>(); }

float m_focalLength { 30 }; //!< millimeters
```

Doxygen commands use `@`, not `\` — `@param`, `@return`, `@note`, `@todo`,
`@brief`. LaTeX in comments is fine and already used (`motion.h` documents its
state vectors with `\f$\dv{\vec r}{t}\f$`).

### File header

Every `.h` and `.cpp` opens with this block, then `#pragma once` for headers:

```cpp
/**

  @file       motion.h
  @brief
  @details    ~
  @author     Viola Case
  @date       13.07.2026
  @copyright  © Viola Case, 2026. All rights reserved.

**/
#pragma once
```

`@date` is the creation date in `DD.MM.YYYY`, not the last-touched date — don't
bump it when you edit a file. Empty `@brief` and `@details ~` are the norm; fill
them in if you have something to say. Field alignment drifts between older and
newer files (`@file      ` vs `@file       `); match the file you're in.

### TODOs

`// TODO` inline (no colon), or `@todo` when there's already a Doxygen block on
the declaration — the latter shows up in the generated docs, which is usually what
you want for a known API-level gap. Multi-line TODOs follow the `/* */` rule above.

Say what's wrong *and* what the fix would be:

```cpp
/* TODO is_number_float() rejects JSON integers, so `"focalLength": 30` silently falls
 * back while `30.0` works. GetInt uses the wider is_number() - this should too. */
```

Swearing in comments is established practice and nobody is going to stop you.

## 2. Formatting

All of this comes from `.clang-format` (LLVM base). Run clang-format; the list is
here so you can read a diff without guessing.

- **2 spaces**, never tabs. Namespaces indent their contents. Access specifiers outdent by 2.
- **120 column** limit. Continuations indent 2.
- **Attached braces** (`BreakBeforeBraces: Attach`) — `{` on the same line, for functions, classes, and control flow alike.
- **Pointer and reference bind right**: `Object *m_object`, `Scene &GetScene()`, `const ParamView &view`.
- **Braced init keeps its spaces**: `Vec3d v { 1, 2, 3 }`, `float m_focalLength { 30 }` — `Cpp11BracedListStyle: false` plus `SpaceBeforeCpp11BracedList: true`. Empty braces stay tight: `Vec3d m_drdt {};`.
- **Short ifs and functions may stay on one line**; short loops may not.
  ```cpp
  if (!m_node) return fallback;
  UUID GetTypeID() const noexcept override { return TypeID(); }
  ```
- **Template declarations always break** before the declaration. A `requires` clause goes on its own line, indented.
- **Preprocessor directives indent inside the `#`** (`IndentPPDirectives: BeforeHash`):
  ```cpp
  #if ROSE_COMPILER_MSVC
    #define ROSE_FORCEINLINE __forceinline
  #endif
  ```
- **Includes are never sorted** (`SortIncludes: Never`) — order is load-bearing, see §4. Blocks are preserved as written.
- Consecutive macro definitions align; trailing comments align.

Files are **LF in the repository** (`.gitattributes` sets `* text=auto`), whatever
your local `core.autocrlf` says.

## 3. Naming

Enforced by `readability-identifier-naming` where clang-tidy can see it.

| Kind | Case | Example |
|---|---|---|
| Class, struct, enum, enum value, concept, template parameter | `PascalCase` | `BehaviorFactory`, `RegisterResult::DuplicateID`, `RegistrableBehavior` |
| Method, free function | `PascalCase` | `FrameUpdate()`, `MakeUnique()`, `Move()` |
| Private member | `m_` + `camelBack` | `m_focalLength`, `m_pendingAdd` |
| Public member (structs) | `camelBack` | `Transform::position`, `Object::transform` |
| Macro | `SCREAMING_SNAKE`, `ROSE_`-prefixed | `ROSE_ASSERT`, `ROSE_FORCEINLINE` |
| Namespace | any case | `ROSE`, `ROSE::math` |
| Function parameter (newer files) | `_` + `camelBack` | `_name`, `_transform` |

Two deliberate exceptions:

- **RTL container members keep STL casing** — `size()`, `empty()`, `push_back()`, `begin()`, `end()`, `find()`, `insert()`, `erase()`, `clear()`, `get()`. This is on purpose so range-`for` and generic code work. Everything that isn't a container member is `PascalCase`.
- **Local `constexpr` config values are lower-case** in example/game code: `constexpr double speed { 500 };`, `constexpr float margin { 24.f };`.

Prefer the `_`-prefixed parameter style in new code; older files leave parameters
bare and that's fine where it already is.

## 4. Headers and includes

- `#pragma once`, never include guards.
- Umbrella header is `<ROSE/ROSE.h>`. `.cpp` files in Core generally include just that; headers include the specific dependencies they need.
- Include paths are angle-bracket and fully qualified: `#include <ROSE/Core/behavior.h>`. Only same-directory example files use `"quotes"`.
- **Include order matters and is not sorted for you.** The layering is:

  ```
  stdlib.h        (the only place <cstring>/<cstdint>/<cmath>/<format>/… are pulled in)
    └── typetraits.h      concepts: Character, StdScalar, Scalar, BehaviorType
          └── utility.h   Move/Forward/Swap/Min/Max, MemCpy, StrLen, …
                └── everything else
  ```

  `ROSE.h` fixes the order `platform.h → macros.h → api.h → rtl.h → … → math.h`, and some
  headers rely on that (`math/vector.h` uses `ROSE_ASSERT` without including
  `macros.h`). See `known-issues.md` #1 before you reorder anything.
- Third-party headers (`nlohmann/json.hpp`, `SDL3/SDL.h`, `imgui.h`) belong in `.cpp` files. Keep them out of public headers — `ParamView` wraps its JSON node in a `const void*` specifically to avoid leaking nlohmann into the API, and `paddle.h` forward-declares `struct SDL_Renderer` rather than including SDL.

## 5. Language rules

- **C++20** (`CMAKE_CXX_STANDARD 20`). Some comments reference C++23/26 features; those are aspirational.
- **Clang in practice** — `clang-cl` on Windows, `clang++`/`gcc` elsewhere. `bigint.h` `#error`s without `__int128` and `mathfunctions.h` leans on `__builtin_*`, so MSVC proper is not a target.
- **No exceptions in engine logic.** Failure paths log and return a fallback. The only `throw`s live in `constexpr`-only paths (`parse128`, `ApplicationFlag`'s constructor) and `std::formatter::parse`. Engine entry points that can fail are `noexcept` and return a null pointer, a sentinel (`UUID::Invalid()`), or a result enum.
- **Use the RTL, not the STL**, in engine code: `String`, `List`, `TypedHashMap`, `Pair`, `UniquePtr`/`MakeUnique`, `Move`, `Forward`. `std::` is acceptable in `.cpp` internals where the RTL has no equivalent (`<random>`, `<chrono>`, `<fstream>`) and at third-party boundaries.
- **Prefer `constexpr`** for type IDs, math constants, and sizes. `Behavior::TypeID()` must be `constexpr` — `Object::CreateBehavior` and `FindBehavior` consume it as a constant expression.
- **`noexcept` on anything that can't throw**, which given the rule above is nearly everything.
- `ROSE_ASSERT` / `ROSE_ASSERT_MSG` are debug-only and compile to `((void)0)` otherwise. Note `_DEBUG` is defined `PRIVATE` on `ROSE_Core`, so assertions are inert in every example and tool target — don't rely on them firing there.

## 6. Behaviors

The full contract is in [`scene-object-behavior.md`](scene-object-behavior.md);
the conventions part:

- Every behavior declares a fresh `typeID` UUID literal, a `constexpr TypeID()`, and an override of `GetTypeID()`. Generate the UUID with `src/Tools/UUIDGenerator`, never by hand and never by copying a neighbor.
- Lifecycle overrides (`OnCreate`, `OnStart`, `FrameUpdate`, `Unpack`) stay `protected` and are marked `override`.
- Behaviors must be default-constructible — the factory mints a blank instance and `Unpack()` fills it in. If you need constructor logic, give it a `noexcept` default constructor that sets sane values, like `Paddle`.
- Register with `MakeBehavior<T>` before any scene loads.

## 7. Cross-cutting

- `#pragma region` / `#pragma endregion` are used to fold long macro and platform sections. Fine to use, don't overdo it.
- `MaxEmptyLinesToKeep: 10` — the tree has large vertical gaps in places. Not a style to imitate, just don't be surprised.
- Prefer fixing a defect over documenting it, but if you can't fix it now, leave a TODO that names the fix (§1) and add it to `known-issues.md` if it's a real trap.
